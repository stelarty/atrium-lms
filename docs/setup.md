# Setup & Frontend Workflow — LMS Атриум

Данный документ описывает **локальную настройку проекта**, правила работы с git и workflow разработки фронтенда для проекта LMS Атриум.
Он предназначен для фронтенд-разработчиков и содержит всю информацию для быстрого старта и безопасной работы с кодом.

---

## 1. Локальная настройка

### 1.1 Клонирование репозитория

```bash
git clone <ssh-or-https-repo-url>
cd <repo-folder>
npm install
```

### 1.2 Запуск проекта

```bash
# Запуск дев-сервера
npm run dev

# Сборка проекта для теста
npm run build

# Локальный тест/preview
npm run preview
```

### 1.3 Структура команд

* `npm run dev` — локальная разработка
* `npm run build` — сборка проекта
* `npm run preview` — просмотр собранного тестового билда

## 2. Git Workflow

### 2.1 Основные ветки

* `dev` — основная ветка разработки
* `main` — ветка продакшн

### 2.2 Рабочие ветки

Создаются **для каждой задачи или исправления**:

* `feature/{название}` — новая функциональность
* `improvement/{название}` — улучшение существующего функционала
* `fix/{название}` — исправление багов

### 2.3 Порядок работы с веткой

1. Создаем рабочую ветку от dev:

```bash
git checkout dev
git pull origin dev
git checkout -b feature/new-component
```

2. Разрабатываем задачу локально.
3. Проверяем изменения:

```bash
git status
git add .
git commit -m "описание изменений"
git push origin feature/new-component
```

4. После завершения задачи — слияние в `dev`:

```bash
git checkout dev
git pull origin dev
git merge feature/new-component
git push origin dev
```

5. Сборка теста через GitLab CI/CD — проверка, что всё работает и тесты проходят.
6. После успешного теста — merge `dev` → `main` через интерфейс GitLab.

### 2.4 Теги и версионирование

**Система тегов:** `MAJOR.MINOR.PATCH` (например, `1.1.0`)

* **MAJOR** — глобальные изменения, несовместимые с прошлой версией
* **MINOR** — новый функционал, совместимый с текущей версией
* **PATCH** — исправления багов, мелкие улучшения

Создание тега после слияния в main:

```bash
git checkout main
git pull origin main
git tag -a 1.1.0 -m "Release 1.1.0"
git push origin 1.1.0
```

## 3. Общие рекомендации

* Работать только через рабочие ветки, не коммитить напрямую в dev или main.
* Писать осмысленные коммиты, чтобы было понятно, что сделано.
* Собирать тестовый билд перед мерджем в main.
* Версионирование строго по правилам MAJOR.MINOR.PATCH.
* Документировать новые компоненты и сторы параллельно с разработкой.
* Писать в тегах подробное описание изменений и проставлять теги `FEATURE`, `IMROVEMENT` и `FIX`

Пример:
```text
FEATURE:
- Создал карточку товара

IMROVEMENT:
- Ускорил загрузку страницы товаров
 
FIX:
- Починил отображение уведомления о добавлении в корзину
```

## 4. Команды для быстрого доступа

| Команда                            | Назначение                    |
| ---------------------------------- | ----------------------------- |
| `npm run dev`                      | Локальный дев-сервер          |
| `npm run build`                    | Сборка тестового билда        |
| `npm run preview`                  | Просмотр тестового билда      |
| `git checkout dev`                 | Перейти в dev для новой ветки |
| `git checkout -b feature/name`     | Создать рабочую ветку         |
| `git add . && git commit -m "msg"` | Зафиксировать изменения       |
| `git push origin <branch>`         | Отправить изменения на GitLab |
| Merge через GitLab                 | Объединение dev → main        |
| GitLab CI/CD                       | Автоматический тест билда     |
