# WidgetTabBar

**WidgetTabBar** — навигационная панель курса для переключения между разделами в LMS Атриум.  
Используется для навигации по курсам (Программа, Расписание, Прогресс и т.д.).  
Состоит из базовых компонентов `BaseTab`.

Компонент является **контролируемым**: состояние `active` управляется через `v-model`.

---

## Особенности

- Управляет активным табом через `v-model`
- Поддерживает отображение иконок слева от текста (через `BaseTab`)
- Реализует горизонтальный скролл на мобильных устройствах
- Скрывает стандартный скроллбар (для кроссбраузерности)
- Семантически корректный HTML (`<nav>`, `<ul>`, ARIA атрибуты)
- Не хранит внутреннее состояние (stateless UI)

---

## Props

| Название   | Тип                      | По умолчанию     | Описание                   |
|------------|--------------------------|------------------|----------------------------|
| `items`    | `TabItem[]`              | —                | Массив элементов меню      |
| `modelValue` | `TabItem\|null`        | `null`           | Текущий активный элемент   |

> ⚠️ Компонент требует `v-model="selectedItem"` привязки в родителе.

---

## Emits

| Событие            | Аргументы  | Описание                      |
|--------------------|------------|-------------------------------|
| `update:modelValue`| `TabItem`  | Обновление активного элемента |

> ⚠️ При выборе таба родитель должен обновить `modelValue`.

---

## Состояния

- **default** — неактивный таб
- **hover** — при наведении на таб
- **pressed** — при нажатии (активное состояние кнопки)
- **active** — выбранный таб с цветовым акцентом

---

## Табы (interface)

```ts
interface TabItem {
  id: string | number
  label: string
  icon?: IconName
}
```

> ℹ️ Определяется внутри компонента. Может быть вынесена в отдельный файл типов при необходимости.

## Примеры использования

### Стандартный

```vue
<script setup lang="ts">
import WidgetTabBar from '@/components/widgets/WidgetTabBar.vue'
import { ref } from 'vue'
import type { IconName } from '@/components/ui/UiIcon.vue'

const activeTab = ref({ id: 1, label: 'Программа', icon: 'list' as IconName })

const tabs = [
  { id: 1, label: 'Программа', icon: 'list' as IconName },
  { id: 2, label: 'Расписание', icon: 'calendar' as IconName },
  { id: 3, label: 'Прогресс', icon: 'fire' as IconName },
]
</script>

<template>
  <WidgetTabBar v-model="activeTab" :items="tabs" />
</template>
```

## Адаптивность

| Экран                    | Поведение                                             |
|--------------------------|-------------------------------------------------------|
| Mobile (< 768px)         | Горизонтальный скролл (`overflow-x: auto`)            |
| Tablet/Desktop (≥ 768px) | То же + плавная прокрутка (`scroll-behavior: smooth`) |

> ⚠️ Скроллбар скрыт во всех браузерах через `-webkit-scrollbar` и `scrollbar-width: none`.

## Архитектурные принципы

- Компонент не управляет своим состоянием напрямую
- Вся логика выбора передаётся через `v-model` и `emit('update:modelValue')`
- Использует семантические теги для доступности (`role="tablist"`, `aria-selected`)
- Все стили `scoped`, импортируются из отдельного SCSS файла
- Соответствует стандартам `workflow.md` §1.3 (префикс `Widget`)
- Не зависит от Store или API
- Является сборкой из `BaseTab` атомарных компонентов

## Возможные расширения

- `loading` (индикатор загрузки активных табов)
- `badge` (бэдж с уведомлением рядом с элементом)
- `disabled` элементы (поддержка в `BaseTab` уже реализована)
- `tooltip` (подсказка при наведении)
- `scroll-to-active` (скролл к активному элементу при загрузке)

## Сравнение с аналогичными компонентами

| Компонент        | Уровень | Ответственность                              |
|------------------|---------|----------------------------------------------|
| `BaseTab`        | Base    | Один таб без состояния                       |
| `WidgetTabBar`   | Widget  | Набор табов + управление состоянием родителя |
| `WidgetDropdown` | Widget  | Выпадающий список с выборками                |

> 💡 `WidgetTabBar` использует `BaseTab` как строительные блоки — это правильный подход по `components.md`.
